## What remains blocked

The LoRA objective predicts each assistant token from the preceding position. The learning-rate schedule uses the full intended optimiser horizon. A segment that stops early is `valid_continuation_required` and does not release final evaluation. `completed` is recorded only after that horizon and a development positive micro-F1 selection. Development selection reads the development split only. `NO_RELATION` is not a positive class. The requested GPU count is not used as the world size. A single-GPU production task loads the model and batches onto the assigned CUDA device and is rejected when CUDA is absent. Qwen3-32B multi-GPU placement is parameter sharding and does not gather the unsharded model onto one GPU before wrapping. Data-parallel training replicates the full parameter set. Rank partitions keep one global effective batch of 16 disjoint across ranks. The matched controller stores each Slurm job identifier and reconciles it with `squeue`, `sacct` and the task's own completion record. A Slurm COMPLETED state without that record is not scientific completion, and a missing queue entry without a terminal `sacct` state is not treated as finished. A technical preflight can release other tasks that use the same execution configuration. It does not count as finished training, and it does not release checkpoint-dependent inference. Queue time and model-loading time are not the useful-computation observation. Preflight requires a recorded start of forward, backward or inference computation and about five minutes after that start, or successful completion of a shorter task. The next controller step is an `sbatch --parsable` submission with `--begin=now+10minutes` and a dependency on the controller job that is exiting. It does not wait for a multi-day representative to finish, and it does not poll from a login node. `production_dispatch run` returns 3 until the approval file matches the checkout. Qwen3.6-27B remains blocked because Transformers 4.57.5 does not recognise `qwen3_5`. GPT-OSS-20B uses its own generation configuration and does not reuse Qwen LoRA module names. Verifier adaptation is not started: the prepared SciFact split does not name a learning rate or an epoch count, and those values are not invented here. Certainty and NLI scoring remain automated provisional measurements. Human judgements remain unfilled. Approval must name `manifest_sha256` of the revision reported by `git rev-parse HEAD`. Earlier digests do not describe this checkout.
